## 问题详解

### F01 原始 HTML 绕过安全边界

**触发条件：** 打开含允许标签及事件属性的 Markdown，再进入预览。例如允许的 `img` 标签可以携带 `onerror`。

**已复现：** 自建文档的事件处理器在没有点击图片的情况下执行，将预览标题改成 `EVENT_HANDLER_EXECUTED`，再向 `toggleTask` 桥接发送 `{line:3,checked:true}`。返回编辑模式后，源文件内容中的测试任务已经从 `[ ]` 变成 `[x]`。测试未发送外部网络请求。

**原因：** `protectRawHTML` 只对白名单标签名进行匹配，却原样保留其全部属性。预览启用 JavaScript；任务桥接只校验参数类型和目标行是否像任务，没有可信事件来源校验。

**影响：** 不可信文档可执行页面脚本、篡改阅读内容及任务状态；已保存文档的任务变更会进入普通自动保存流程。文档内容外传是需要进一步验证和封堵的风险。本次未证明任意本地文件读取或系统命令执行，不将其称为远程代码执行漏洞。

**建议：** 先关闭未经清洗的原始 HTML，或采用严格的标签、属性、URL 协议白名单；删除所有事件属性。将应用脚本与文档内容隔离，收紧桥接权限，再用适当的内容安全策略限制资源和脚本。编码后的危险 URL 也应在解码、规范化后校验：探针还发现 `javascript&#58;` 会保留到导出的链接属性中。

**验收：** 上述输入在预览、PDF 准备和导出 HTML 中均不执行；安全标签、公式和图表仍可使用；伪造任务消息不能改变文档。

证据：[原始 HTML 透传](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2Core/MarkdownRenderer.swift#L1455)、[桥接入口](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MarkdownPreviewView.swift#L1345)、[危险协议匹配](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2Core/MarkdownRenderer.swift#L2664)。

### F02 文档规模增长会直接阻塞输入与窗口响应

`DocumentStore` 的 120 ms 防抖最终调用 `@MainActor` 上的同步全文渲染；延后执行并没有把计算移出主线程。与此同时，`textDidChange` 每次输入都会重置全文属性、扫描块和行内样式，并要求重绘。

| 中英文标题和列表密集样本 | 行数 | 全文渲染中位数 | 全文样式处理中位数 |
| --- | ---: | ---: | ---: |
| 约 10 KB | 568 | 46.9 ms | 2.4 ms |
| 约 100 KB | 5,692 | 461.4 ms | 21.2 ms |
| 约 500 KB | 28,456 | 2,372.3 ms | 137.0 ms |
| 约 1 MB | 56,911 | 4,597.2 ms | 303.2 ms |

这些是结构密集的合成文档，不能推广为所有同体积文档的耗时。小型真实文件作为对照：5.7 KB 的中文 README 渲染中位数 11.2 ms，6.2 KB 的 Sample 渲染中位数 24.4 ms；样式处理分别约 1.1 ms 和 1.2 ms。

**影响：** 较大文档停顿输入后，渲染会抢占主线程；继续键入、切换模式和保存可能等待计算完成。即使只处于编辑模式，文档变化仍会生成完整预览和统计。空文档生成的 HTML 已有 686,748 字节，始终内联数学引擎也是后续优化点。

**建议：** 使用后台渲染与版本号丢弃过期结果；将编辑器样式更新限定在受影响的语法块；统计、大纲与 HTML 按需要更新；按需加载引擎并复用预览容器。先消除主线程阻塞，再讨论渲染缓存和局部 DOM 更新。

**验收建议：** 为 10 KB、100 KB、1 MB 文档分别测量真实输入、滚动和切换的 p50/p95；100 KB 基准文档的输入到显示 p95 以低于 50 ms 为首轮目标。不能仅以总渲染变快或防抖增加判定通过。

证据：[主线程渲染](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/DocumentStore.swift#L697)、[逐次全文样式更新](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MarkdownEditorView.swift#L1279)、[样式重置](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MarkdownTextStyler.swift#L8)、基准原始输出（本地生成记录：`.audit/2026-10-15/benchmark.log`）。

### F03 短而异常的输入也会造成长时间无响应

**复现输入：** 单行连续的 `[`，没有闭合分隔符。

| 字符数 | 渲染中位数 | 样式处理中位数 |
| ---: | ---: | ---: |
| 1,000 | 7.4 ms | 4.9 ms |
| 5,000 | 164.8 ms | 121.4 ms |
| 10,000 | 653.2 ms | 481.9 ms |
| 20,000 | 2,591.6 ms | 1,944.2 ms |

字符数从 10,000 增到 20,000，耗时接近原来的 4 倍。样式匹配中的链接正则会在多个起点重复扫描没有右括号的后缀；渲染器也有同类扫描路径。这与普通大文档的线性工作量问题不同，单纯增加防抖不能解决。

**建议：** 对未闭合结构采用有界、线性扫描；避免在整个后缀反复尝试同一模式；补充分隔符、长行和深嵌套的退化测试与可取消渲染机制。

**验收：** 输入长度翻倍不再使耗时接近 4 倍；异常文档不会阻塞用户关闭窗口或继续编辑。

证据：[样式链接正则](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MarkdownTextStyler.swift#L180)、[渲染链接匹配](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2Core/MarkdownRenderer.swift#L1901)、探针数据（本地生成记录：`.audit/2026-10-15/adversarial-benchmark.log`）。

### F04 双栏数学宏更新后显示旧结果

**复现：** 在 front matter 定义 `math-macros: {"\\audit": "A"}`，正文使用 `$\audit$`。进入双栏后把宏定义的 `A` 改为 `B`，左侧源码显示 `B`，右侧仍显示 `A`。

**原因：** 实时更新只替换正文，公式重渲染仍从页面初次加载时的 `__md2InitialMacros` 读取定义；是否允许局部更新的判断没有包含宏配置变化。

**建议及验收：** 把宏配置作为预览更新协议的一部分，或配置变化时重新加载。新增、修改、删除宏后，双栏、阅读和导出应得到一致结果。

证据：[局部更新判断](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MarkdownPreviewView.swift#L709)、[替换正文](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MarkdownPreviewView.swift#L441)、[宏初始化](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2Core/MarkdownRenderer.swift#L2366)。

### F05 预览过期时可能修改另一条任务

**确定性探针：** 预览生成时第一行是任务 A；随后源码在首行插入任务 N，尚未更新的预览仍将 A 标记为第一行。此时处理 `toggleTask(line:1)`，实际勾选的是 N。

这不是任意文本覆盖：接收端确实验证了目标行是任务。但“目标仍是任务”不等于“仍是用户点击的那条任务”。实际鼠标操作中的触发概率未测量，模型层已确认接受过期行号。

**建议及验收：** 桥接消息携带渲染版本和任务标识；版本失效时拒绝或重新定位。插入、删除、移动任务后，旧预览消息不得修改其他任务。

证据：[任务处理](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/DocumentStore.swift#L537)、探针输出（本地生成记录：`.audit/2026-10-15/document-probes.log`）。

### F06 PDF 导出错误地要求源目录可写

**复现：** 源目录权限设为 `0555`，其中 Markdown 可读；导出目标放在可写目录。纯文本文档仍返回 `preparationFailed`，不生成 PDF。

**原因及影响：** 导出前必须在源文件旁创建 `.md2-preview-*.html`。只读共享目录、只读挂载等合法阅读场景因此不能导出；打印复用该导出器，也受相同路径约束。

**建议及验收：** 临时渲染文件放入应用缓存或临时目录，图片沿用已有白名单协议加载。纯文本、相对图片和父目录图片在只读源目录下均能导出到可写位置，且不污染源目录。

证据：[源目录写入](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/PDFExporter.swift#L231)、[打印复用链路](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/DocumentPrinter.swift#L36)、测试结果（本地生成记录：`.audit/2026-10-15/readonly-pdf-probe.log`）。

### F07 草稿恢复能力不足

这是可靠性能力缺口。未命名文档不会进入自动保存；已保存文档采用停止输入 5 秒后的保存，每次输入都会重新计时，没有独立的最长未持久化时间。关闭确认只覆盖正常退出，不能恢复进程异常结束后的内存内容。

安装版退出异常后，重新打开只出现起始文档，之前的审查草稿未恢复。当前源码未发现草稿恢复存储或恢复入口。

**建议及验收：** 对未命名和已保存文档建立独立恢复副本，设置保存最大等待时间；正常保存后清理恢复状态。用独立测试文档模拟进程终止，重启可找回最近内容，同时保留外部修改冲突保护。

证据：[自动保存入口](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/DocumentStore.swift#L904)、[正常关闭确认](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MD2AppDelegate.swift#L386)。

### F08 HTML 导出没有兑现完整离线承诺

**复现：** 导出包含远程图片链接的 Markdown，产物仍保留原始 HTTPS `src`。不存在的本地文件和无法解析的相对路径也被保留，导出仍报告成功。

保留远程资源可以是合理策略，但 README 宣称“图片全部内联、可离线打开”，目前没有与之匹配的保证或结果提示。

**建议及验收：** 明确区分“自包含导出”和“保留外链导出”；自包含模式应收集可获取资源，对失败资源展示清单。断网并移走源目录后验证图片仍可见，或者用户已收到明确的不完整提示。

证据：[保留远程资源](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/SelfContainedHTMLBuilder.swift#L47)、[产品承诺](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/README.zh-CN.md#L30)、探针输出（本地生成记录：`.audit/2026-10-15/document-probes.log`）。

### F09 测试资产没有成为发布门槛

仓库中只有标签触发的发布工作流，直接构建、打包和创建 Release，没有 `swift test` 步骤。普通本地测试又跳过了 44 项界面等测试。仓库外是否另设检查，本次未核实，不能推断不存在。

**建议：** 为 PR 和标签发布执行核心测试；按套件隔离运行编辑、模式切换、查找、导出与启动的 GUI 测试。已有 TODO 记录多个 GUI 套件同进程运行时的窗口销毁崩溃，因此不宜直接把全部 GUI 测试合并成一次执行。

**验收：** 核心测试失败阻止发布；主要 GUI 套件的执行与跳过数量可见；覆盖最低支持版本 macOS 15 和当前开发系统。

证据：[发布工作流](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/.github/workflows/release.yml#L11)、[已知测试设施问题](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/TODOS.md)。

### F10 核心模式切换被次要按钮挤入溢出区

**已观察：** 中文界面、约 980 pt 宽窗口、带 front matter 的双栏文档中，工具栏保留“打开”“保存”“显示元数据”，编辑／双栏／预览切换控件却进入右侧溢出菜单。用户刚进入双栏后，返回其他模式的主要入口变得不直接。

**原因：** 模式控件固定宽度 280 pt，与多个完整文字按钮共同竞争空间，缺少优先保留策略。

**建议及验收：** 固定保留模式切换，优先折叠次要操作；为窄窗口提供紧凑模式控件。在中文、英文、长文件名以及有无元数据的窗口中验证。

证据：[工具栏布局](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/ContentView.swift#L243)、[固定宽度模式控件](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/ContentView.swift#L278)。

### F11 最近文档菜单不能及时反映当前会话

代码明确记录：设置窗口关闭时，文件菜单使用启动时的最近文档快照，Dock 菜单才是实时列表。用户打开新文档后，两个入口可能呈现不同结果。

**建议及验收：** 在菜单打开时动态更新，或使用可靠的观察机制。同一会话内打开、保存、清空最近文档后，文件菜单和 Dock 菜单应一致。

证据：[启动快照说明](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Sources/MD2App/MD2App.swift#L77)。

### F12 支持说明与产品行为不一致

`Docs/MarkdownSupport.md` 的“不支持”部分仍将 PDF 导出列在其中，但 PDF 已实现且本次测试通过。同一文档还称拖入的图片会保存到附件目录，而实现和 README 明确是直接引用现有位置。兼容性矩阵的附件描述也需要同步。

**建议及验收：** 以功能与支持矩阵为统一来源生成说明；修正 PDF、附件和 HTML 导出的边界描述。文档应清楚区分未支持、部分支持、已实现但有条件的能力。

证据：[过时的 PDF 描述](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/Docs/MarkdownSupport.md#L40)、[正确的附件说明](https://github.com/stutiredboy/Markdown2/blob/7d7df83ed35c57bff326c305a2333654eeb8fbd3/README.zh-CN.md#L28)。

## 安装版异常与尚未关闭的调查项

**R01：编辑 → 预览 → 编辑 → Cmd+Z 后应用退出，建议按 P1 调查。**

在安装版、独立未保存测试文档中观察到两次退出；工具分别报告窗口不可用和 `App quit`，进程检查也未见原进程。重新打开后未恢复测试草稿。尚未取得有效崩溃堆栈。

当前源码的最小 NSHostingController 测试确认模式切换会重建编辑器，但旧编辑器仍存活，撤销能够正常回写源文本，**没有复现退出，也没有证据支持“切换必然清空撤销历史”**。隔离应用的桌面复测遇到自动化连接与调试器问题，不能把这些工具超时算作应用缺陷。

下一步应复用完整的粘贴、追加、模式切换、点击定位、菜单撤销路径，对安装版和最新构建各做重复实验，捕获进程退出原因；再区分 AppKit 撤销目标生命周期、原生菜单路由与自动化输入因素。该项不能作为当前源码已确认崩溃计数。

证据：当前源码撤销探针（本地生成记录：`.audit/2026-10-15/undo-current-source.log`）。

## 优化决策建议

| 顺序 | 投入方向 | 完成标准 |
| --- | --- | --- |
| 第一批 | F01 内容安全；并行定位 R01 安装版退出 | 文档脚本不能进入应用权限边界；退出异常取得明确原因或稳定排除条件 |
| 第二批 | F02 主线程计算、F03 退化输入、F07 草稿恢复 | 输入响应有量化预算；异常输入可取消；异常退出有恢复路径 |
| 第三批 | F04 宏更新、F05 任务身份、F06 权限边界、F08 导出完整性 | 预览、源码和产物一致；失败条件能够解释且不破坏数据 |
| 持续配套 | F09 测试门槛、F10 工具栏、F11 最近文档、F12 文档 | 每次发布可验证，主要操作入口稳定可见 |

对技术写作定位，后续兼容性投入优先考虑参考式链接、复杂列表、嵌套公式交叉引用和分隔符归属。项目已经记录了容器内公式前向引用及混合数学分隔符的局限，应作为已有技术债处理，而不是重复登记为本次新发现。对跨机器协作定位，可再考虑图片复制／收集与“另存为”；当前绝对路径链接是明确的产品选择，移动图片后失效属于该选择的可移植性代价。

暂缓 DOCX/EPUB 菜单扩展、更多主题和更多语法糖。现有功能已经足以暴露核心链路问题，优先让现有路径安全、流畅、可靠，能获得更直接的用户收益。
