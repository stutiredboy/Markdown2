## 3. Menu-bar localization (issue #2)

- [x] 3.1 Add a language-code resolver in `AppSettings` mapping the **stored** `language` value (not `effectiveLanguage`) to `AppleLanguages` codes: `.english → ["en"]`, `.zhHans → ["zh-Hans"]`, `.system → nil` (remove override)
- [x] 3.2 Add a startup routine that writes/removes the `AppleLanguages` UserDefaults override based on the stored `MD2.Language`, and call it in `MD2Application.init()` *before* `DirectLaunchBootstrap.relaunchFromAppBundleIfNeeded()`
- [x] 3.3 Implement a **terminate-first** relaunch flow — do **not** launch-then-terminate: `NSWorkspace.openApplication` on the already-running `.app` reactivates the existing instance instead of spawning a new process, so launch-first either no-ops the relaunch or (with `createsNewApplicationInstance`) strands two instances on cancel. Instead: Restart Now sets a `pendingLanguageRelaunch` flag on `MD2AppDelegate` and calls `NSApp.terminate(nil)` (not `exit()`, so `applicationShouldTerminate`'s unsaved-changes loop runs and a cancel aborts the relaunch). In `applicationWillTerminate`, if the flag is set, spawn a **detached** `Process` (`/bin/sh -c 'while kill -0 <pid> 2>/dev/null; do sleep 0.2; done; open "<bundle>"'`) that waits for the current PID to exit then re-opens the bundle. Reserve the `MARKDOWN2_LANGUAGE_RELAYOUT_DONE` env flag for the fallback auto-relaunch path only.
- [x] 3.4 In `SettingsView`, detect a language change (e.g. `.onChange(of: settings.language)`) and present a localized alert (Restart Now / Later); Restart Now triggers the terminate-first flow from 3.3. Cancelling the unsaved-changes prompt during termination aborts the relaunch (nothing was launched yet).
- [x] 3.5 Verify custom command items still update immediately on language change (no regression — they use `@Published language` via `AppSettings.text(_:)`)
- [x] 3.6 **Verify** on macOS 14+ that `AppleLanguages` override localizes standard AppKit menus (File/Edit/View/Window/Help, system items) even without app-bundle `.lproj` resources. If it does not, add `CFBundleLocalizations` (`["en", "zh-Hans"]`) to the runtime `Info.plist` generated by `RuntimeAppBundleBuilder`.

## 5. Print command (issue #4)

- [x] 5.1 Add a `DocumentPrinting` protocol (parallel to `PDFExporting`) and a `DocumentPrinter` that: (a) renders to a temp PDF via the existing `PDFExporter` pipeline, (b) loads it with `PDFKit.PDFDocument`, (c) calls `PDFDocument.printOperation(for:scalingMode:autoRotate:)` to get a standard `NSPrintOperation`, and runs it. **No custom paginated `NSView`** — use the built-in PDFKit API.
- [x] 5.2 Temp PDF is written to `FileManager.default.temporaryDirectory` (not the document directory — untitled documents have no `baseURL` directory). The temp file is deleted in the print operation's completion handler (success or failure). **Do not rely on the preview's `sweepStalePreviewFiles`** — it only matches `.md2-preview-*.html`.
- [x] 5.3 Add `DocumentStore.print()` mirroring `exportPDF()`: flush pending render; do not mutate `fileURL`/`isDirty`/autosave; surface failures via `DocumentAlert`. Make Print and Export **mutually exclusive** — note `pdfExporter` is typed `PDFExporting?` and cannot also hold a `DocumentPrinter`, so add a single shared in-flight guard (e.g. a `derivedArtifactInFlight` flag, or retain the printer in its own property and check both) set on start and cleared in the completion handler
- [x] 5.4 Add a Print command in `MD2App.swift` via `CommandGroup(replacing: .printItem)` with ⌘P, titled `settings.text(.print)`, calling `appDelegate.currentDocumentStore?.print()`. The optional chaining makes it a safe no-op when no document is focused (consistent with existing Save/Export commands — they are not greyed out either).
