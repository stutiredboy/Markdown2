## 2. Native environment block math

- [ ] 2.1 Define the recognized-environment set as one named constant, enumerated (review decision D2): display environments `align`, `align*`, `alignat`, `alignat*`, `gather`, `gather*`, `equation`, `equation*`; standalone inner environments `aligned`, `alignedat`, `split`, `cases`, `array`, `matrix`, `pmatrix`, `bmatrix`, `Bmatrix`, `vmatrix`, `Vmatrix`, `smallmatrix`. Engine-rejected names also recognized (`multline`, `eqnarray`, `displaymath`, `subequations`) so they surface a visible engine error.
- [ ] 2.2 Extend `mathBlockContent` with a `\begin{<env>}` branch. Parse the environment name from the opening line and scan forward for a line whose trimmed content ends with the matching `\end{<env>}`, reusing the existing single-line/multi-line split shape, with three review-mandated exceptions (D1/D6/D7):
  - **The returned TeX retains both environment commands.** The `$$`/`\[` branches strip their delimiters; the env branch must NOT — a single-line form keeps `\begin{env}…\end{env}` intact and the multi-line form keeps the open and close lines. Stripping them sends bare TeX (`a&=b`) to KaTeX, which parse-errors (probe-verified).
  - **Same-name depth counter.** Nested same-name environments are valid KaTeX (`matrix` inside `matrix` typesets), so counting depth on `\begin{<same>}`/`\end{<same>}` and closing at depth zero prevents silent truncation. Different-name inner closers never match, as before.
  - **Fence bail.** If the forward scan hits a fenced-code opener (via `MarkdownLine.fenceMarker`) before the closer, return `nil` so the text falls through literally. Real environments never contain fences; this prevents prose-plus-fenced-sample capture.
- [ ] 2.3 Confirm the four `mathBlockContent` call sites need no edits — the render walk, the paragraph-break check, the footnote scan, and the `\label` pre-scan — so equation numbering and `\ref{}` resolution extend to environments for free **for top-level blocks** (review decision D9). Scope note for the docs/matrix text: the pre-scan does not traverse blockquotes or dedented list content (pre-existing asymmetry), so a forward `\ref{}` targeting an equation inside a container may stay unresolved; that limitation is documented and tested (3.2), not fixed here.
- [ ] 2.4 Confirm the new branch does not weaken code precedence: the fenced-code check still runs before math in the render walk, and indented code still wins.
